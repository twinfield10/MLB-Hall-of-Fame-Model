# ⚾ MLB Hall of Fame Model

![status](https://img.shields.io/badge/status-in%20progress-yellow)

A machine-learning pipeline that estimates every eligible player's probability of
election to the Baseball Hall of Fame, from historical
[Lahman](https://sabr.org/lahman-database/) data plus Baseball-Reference WAR.
Separate models are trained for **batters** and **pitchers**, and — because the Hall is
elected by distinct bodies — the model is **committee-specific**: it predicts the
Baseball Writers' (BBWAA) vote by default, projecting each candidate's ballot share and
converting it into election odds via Monte-Carlo simulation.

## How the model works

The Hall is elected by different bodies with different rules, so the pipeline is
**committee-specific** (`model.committee` in `config.yml`):

### 1. `bbwaa` — the writers' vote *(default)*

The most rule-bound and predictable route, modeled in three linked stages:

1. **Vote-share regressor.** An XGBoost model (`xgbTree`) predicts a player's ballot vote
   share (`votes / ballots`) for a cycle. The unit of analysis is the **player-ballot-year
   panel** — one row per *actual* BBWAA ballot appearance since 1936, reconstructed from the
   `HallOfFame` table. Training on real ballot rows makes eligibility self-enforcing (10+
   seasons, 5 years retired, 5% survival, ≤10-year tenure).
2. **Leak-free features.** Ballot-history features are computed **strictly from prior years** —
   `appearance_number`, `prev_share`, momentum (`prev_delta`), `max_share_prior`,
   `years_remaining` — joined to a full career-merit matrix (WAR, JAWS, Bill James HOF Monitor,
   PED flag). Rule-of-10 "ballot crowding" features (`competitor_mass`, `n_strong_competitors`)
   let borderline candidates separate upward on a weak ballot.
3. **Monte-Carlo forward simulation** (`simulate_bbwaa`, 2,000 sims/candidate). Each candidate is
   rolled forward year by year — re-feeding each simulated season's share as next year's
   `prev_share`, adding **heteroscedastic noise** (residual spread grows near the 75% boundary),
   and applying the real election/survival/tenure rules. This turns one share prediction into
   `P_elected_cycle` and `P_eventual_bbwaa`.

> **Why grouped CV matters.** The share regressor is validated with **leave-one-cycle-out**
> (grouped by ballot year), not random k-fold — a player's adjacent ballot years are
> autocorrelated through `prev_share`, so random folds would leak the answer.

### 2. `any_route` — induction by *any* body

The original formulation: a binary XGBoost classifier (`xgbLinear`, 10-fold CV) predicting
`P(inducted by any committee)` as a single `HOF_Prob`, from the wide **top-20-seasons-by-WAA**
career-merit matrix.

### Model design details

- **Pluggable engines** — `xgbLinear` (default) · `xgbTree` · `glmnet` · `randomForest`, swappable via `config.yml`.
- **Severe class imbalance** (~1–4% positive) is handled natively; config-gated options for
  up/down-sampling and class weights were evaluated and *reduced* quality, so the default is off.
- **Probability calibration** (Platt / isotonic) available; the base model is already
  well-calibrated (Brier ≈ 0.006), so it's off by default.
- **Experimental 4-class label** (`FirstBallot | BBWAA | VetCom | No`) via a multinomial model —
  macro one-vs-rest AUC **0.989**.
- **No temporal leakage** — HOF labels are capped at `season − 1` so the model never trains or
  evaluates on the season it's predicting; active players are given an effective final season so
  they're scored. See [`docs/MODELING.md`](docs/MODELING.md).

## Model performance (held-out)

Every model is scored on its **cross-validated out-of-fold** predictions — genuine held-out
predictions on players whose fate is already decided — not the training set.

**`any_route` binary classifier** (2026 cycle, 2025 snapshot):

| Model | ROC-AUC | PR-AUC | Log-loss | Brier | Precision@k | n / positives |
|-------|:---:|:---:|:---:|:---:|:---:|:---:|
| Batters | 0.997 | 0.944 | 0.027 | 0.006 | 0.915 | 1,892 / 71 |
| Pitchers | 0.994 | 0.877 | 0.020 | 0.005 | 0.812 | 5,317 / 80 |

**`bbwaa` vote-share & election model:**

| Model | Share MAE | Share corr | Election ROC-AUC | Election PR-AUC | n / elected |
|-------|:---:|:---:|:---:|:---:|:---:|
| Batters | 0.048 | 0.919 | 0.959 | 0.698 | 2,605 / 91 |
| Pitchers | 0.044 | 0.927 | 0.968 | 0.616 | 1,284 / 46 |

**PR-AUC is the headline metric** here — under this much class imbalance, ROC-AUC flatters
everything. Metrics are regenerated to `outputs/metrics/eval_*.yml` on every run.

## Reproducibility & the temporal design

This repo is a **reproducible refactor** of a legacy interactive R workflow. The design goal:

> **Rolling to a new season = change one config value + drop in a new data snapshot + run one
> command.** No code edits, no scattered hardcoded years.

Two anchors drive every date; nothing temporal is hardcoded elsewhere:

- **`season`** — the induction cycle being predicted (the one yearly knob in `config.yml`).
- **`DATA_SEASON`** — the max `yearID` in the snapshot, **read from `MANIFEST.yml`** and validated,
  never typed.

`R/config.R::load_config()` derives the train/test windows, HOF-eligibility cutoff, "active
player" threshold, player-age reference, and Veterans-Committee scan window from those two.
`validate_vintage()` fails loudly if the snapshot is stale or internally inconsistent.

Other reproducibility guarantees:

- Dependencies declared in `DESCRIPTION`, pinned in `renv.lock` (R 4.3.2). Rebuild the exact
  environment with `renv::restore()`.
- The Baseball-Reference WAR pull is **cached and fetch-date-stamped** under `Data/cache/`, so runs
  are deterministic and offline-capable (set `live_refresh: true` to re-pull).
- Trained models persist to `outputs/models/<type>_<season>.rds` with a `.meta.yml` sidecar
  (season, data vintage, snapshot, seed, engine, feature columns, tune, metrics).
- The refactor is **parity-gated**: it reproduces the legacy 2026 predictions exactly before any
  behavior change. See [`docs/PARITY.md`](docs/PARITY.md).

### Rolling to a new season

1. Download the latest Lahman CSV release into `Data/snapshots/lahman_<YEAR>/`.
2. `Rscript -e 'source("R/data_snapshot.R"); build_manifest("Data/snapshots/lahman_<YEAR>")'`
3. In `config.yml`: set `season:` and point `snapshot:` at the new folder.
4. If ballot/current-season data isn't in the snapshot yet, add a `Data/supplement/supplement_<YEAR>.csv`
   and `Data/ballots/ballot_<SEASON>.yml`.
5. `Rscript run.R` — rebuilds features, models, predictions, metrics, and report.

## Quick start

```bash
# 1. Restore the exact package environment
Rscript -e 'renv::restore()'

# 2. Train + predict for batters & pitchers -> outputs/
Rscript run.R                      # uses `season` from config.yml
Rscript run.R 2027                 # or override the season

# 3. Render the gt "Cooperstown likelihood" tables -> outputs/reports/*.html
Rscript Scripts/render_report.R

# 4. Verify predictions still match the frozen golden set
Rscript Scripts/parity_report.R

# 5. Compare imbalance / calibration / 4-class options
Rscript Scripts/modeling_experiments.R

# 6. Run the test suite
Rscript -e 'testthat::test_dir("tests/testthat")'
```

## Project layout

```

run.R                 # one-command orchestrator: load -> features -> train -> predict
R/                    # function library (sourced in dependency order by run.R)
  config.R            #   load_config(): derives every date from `season` + DATA_SEASON
  data_snapshot.R     #   get_table(), build_manifest(), validate_vintage()
  feature_matrix.R    #   shared career-aggregation / WAR-append core
  features.R          #   append_*() feature builders
  assemble.R          #   batter/pitcher feature-assembly chains
  ballot_features.R   #   BBWAA player-ballot-year panel + ballot-history features
  model.R             #   engine registry, train/predict, calibration, persistence
  evaluate.R          #   held-out metrics from CV out-of-fold predictions
  committee_bbwaa.R   #   BBWAA share regressor + Monte-Carlo forward simulation
  labels.R            #   experimental 4-class label + multinomial model
  report.R            #   gt "Cooperstown likelihood" tables
Data/
  snapshots/          # immutable dated Lahman CSVs + MANIFEST.yml (source of truth)
  supplement/         # current-season data not yet in a snapshot
  ballots/            # per-cycle BBWAA ballot (manual input)
  cache/              # cached live pulls (git-ignored)
outputs/{models,predictions,metrics,reports}/
Scripts/              # helper CLIs (parity, report, experiments, projections, lockfile)
tests/{testthat,golden}/   # unit tests + frozen-output regression oracle
archive/legacy/       # the original scripts, kept for reference, never sourced
docs/                 # MODELING.md, PARITY.md
```

## Roadmap

The refactor is **phased and parity-gated** — each phase reproduces prior predictions exactly
before adding behavior.

- [x] **Phase 0–2** — freeze golden outputs, archive legacy scripts, single-snapshot data layer.
- [x] **Phase 3** — all dates derived from `season`/`data_season`; active players scored; labels capped at `season − 1`.
- [x] **Phase 4** — de-duplicated batter/pitcher paths into one core; byte-identical to baseline.
- [x] **Phase 5** — model module + persistence with `.meta.yml`; held-out CV evaluation.
- [x] **Phase 6** — config-gated imbalance handling, calibration, and experimental 4-class label.
- [x] **Phase 7** — `gt` reports, restorable `renv.lock`, docs.
- [ ] **Next** — a `{targets}` DAG for per-stage caching / dependency tracking; Veterans/Era-committee models.

See [`docs/MODELING.md`](docs/MODELING.md) and [`docs/PARITY.md`](docs/PARITY.md) for detail.
